# M4-05 后端执行任务：非法请求体处理

> **任务角色：** 后端实现
>
> **批准角色：** 协调 PM
>
> **任务日期：** 2026-08-13
>
> **任务状态：** 待执行

> **任务依据：** `pm/requirements/2026-08-13/m4-task-design.md` §3 M4-05（设计已获用户批准，2026-08-13 分节确认）；执行与验收流程见该设计 §4（沿用 G1-04 模型）。

## 1. 任务摘要

确认非法 UTF-8 / 畸形 JSON 等非法请求体归类 400（HTTP 400 + 业务 code + 统一响应体，对齐 G1-02 语义），必要时调整全局异常处理器映射，并补齐全局异常映射测试。

## 2. 前置事实（PM 已核验）

### 2.1 任务来源

`pm/requirements/2026-08-13/m4-task-design.md` §3 M4-05（M4 六项任务之一，无依赖）：

- 背景：「非法 UTF-8 等异常请求体的归类与异常映射未确认。」
- 范围：「异常映射（全局异常处理器）、非法请求体行为确认与测试。」

### 2.2 现状（M3 联调记录 §10.4 已核验）

`acceptance/backend/milestones/M3/2026-08-02/M3联调记录.md` §10.4 记录：

- 客户端以非 UTF-8（GBK）字节发送 JSON 时，Jackson 解析抛异常，被 `GlobalExceptionHandler` 兜底为 **500**（`{"code":500,"message":"系统繁忙,请稍候再试","success":false}`）。
- 记录建议 M4 评审将请求体解析类异常（`HttpMessageNotReadableException`）映射为 400，与统一参数校验异常对齐。

### 2.3 统一响应体与既有 400 结构（不重复执行）

- 统一响应体 `ResponseResult`：`success` / `code` / `message` / `data`（Auth / Subject / OSS 共用，见 M3 联调记录 §6.4）。
- 既有 400 结构（OSS 非法参数）：`{"code":400,"data":null,"message":"参数校验失败","success":false}`（M3 联调记录 §6.4）。

### 2.4 G1-02 统一语义（已关闭，本任务沿用）

- 统一语义：HTTP 状态、业务 code、响应结构、前端处理方式和测试（见 `pm/reviews/2026-08-10/gate-0-1-contract-reconciliation-checklist.md` G1-02 行）。
- 本任务将非法请求体归类 400 并对齐该语义，与 §2.3 既有 400 结构保持一致。

## 3. 执行步骤（按顺序执行）

### 步骤 1：构造非法请求并实测（真实 HTTP 调用）

- 构造非法 UTF-8 与畸形 JSON 两类请求体（如 GBK 编码字节、截断/重复键等畸形 JSON），对后端接口发起真实 HTTP 调用（触发方式参考 M3 联调记录 §10.4）。
- 记录原始请求与原始响应（含 HTTP 状态、业务 code、响应体），供回执附完整证据。

### 步骤 2：确认归类 400 并补齐异常映射

- 确认非法请求体归类 400：HTTP 400 + 业务 code + 统一响应体，对齐 G1-02 语义与 §2.3 既有 400 结构。
- 若实测未归类 400：调整全局异常处理器，将请求体解析类异常（如 `HttpMessageNotReadableException`）映射为 400（对齐 M3 联调记录 §10.4 建议）；不得改变已批准契约的字段/路径/方法。

### 步骤 3：补齐全局异常映射测试

- 全局异常映射测试覆盖非法请求体（非法 UTF-8 / 畸形 JSON），断言 HTTP 400 + 业务 code + 统一响应体（对齐 `SubjectContractTest` 风格）。

### 步骤 4：运行测试（预期全绿）

- 异常映射测试通过；既有测试全绿（infra / domain / controller 契约测试）。

### 步骤 5：提交回执（执行后由 后端评审 复核签署）

回执文件：`handoff/backend-to-frontend/<执行日期>/m4-05-invalid-request-body-report.md`（回执目录按回执实际创建日期落位，即执行者写回执当天，AGENTS.md 第 6 条），必须包含：

1. 来源项目、分支、实施提交哈希与回执提交哈希。
2. 实测请求/响应记录：非法 UTF-8 与畸形 JSON 各一组的原始请求与原始响应（HTTP 状态、业务 code、响应体）。
3. 异常映射测试命令与原始输出。
4. OpenAPI 是否变化及结论（如变化，记录提案编号，见禁止事项）。
5. 已知限制（如未覆盖的非法输入类型、服务地址、环境变量）。
6. 声明：未修改交接仓库 `api/` 快照、`status/sync-manifest.json`；未伪造验证输出。

## 4. 验收边界与关闭条件

- 本任务仅覆盖非法请求体（非法 UTF-8 / 畸形 JSON）的归类 400 与全局异常映射测试；不得自行改变已批准契约的字段/路径/方法（如有需要必须先提案）。
- 关闭条件（全部满足后 PM 复核关闭 M4-05）：
  1. 非法 UTF-8 与畸形 JSON 请求实测返回 400（原始请求与响应记录，含 HTTP 状态、业务 code、统一响应体）。
  2. 全局异常映射测试通过（异常处理器覆盖非法请求体）。
  3. 既有测试全绿（infra / domain / controller 契约测试）。
  4. 回执含原始请求/响应、测试输出与提交哈希，后端评审 复核签署。
- 若实测发现非法请求体无法归类 400，或调整异常映射涉及错误码/响应结构等契约变更：**M4-05 不关闭**，契约变更先写入 `proposals/backend/`，经 PM 确认后实施，再重新验证。

- 不得在回执中伪造请求、响应或测试输出。

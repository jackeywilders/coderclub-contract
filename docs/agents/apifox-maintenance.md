# Apifox 接口维护治理（2026-08-30 生效）

> 三角色共识：B-Impl 执行 / B-Review 复核 / PM 知会。权威细则来源：CoderClub 仓库 `AGENTS.md`「Apifox 接口维护」小节（避免双份漂移）。

## 角色分工

- **B-Impl**：按 CoderClub `AGENTS.md`「Apifox 接口维护」小节执行 Apifox 同步（导入 / 逐项比对 / 定点修复 / 环境与目录维护）；新服务接入先提醒用户建模块。
- **B-Review**：导入 / 同步后复核——新端点组织（模块/目录归属）、既有接口 schema 与源契约一致性、环境无重复。
- **PM**：新服务接入 Apifox 时先行创建模块（界面操作——MCP / 客户端均无模块 API）；治理条目生效与更新知会。

## 关键约束

1. 新服务模块**先建后维护**；禁止默认模块导入后搬移。
2. 增量同步须**逐项比对**既有接口 schema（导入默认不覆盖）。
3. 踩坑清单与流程细则以 CoderClub `AGENTS.md` 小节为权威来源。

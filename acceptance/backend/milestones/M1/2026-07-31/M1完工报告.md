## 3. 关键设计决策

### 3.1 `ResultCodeEnum.FAIL` = 999

计划要求 FAIL=999（前端 Axios 拦截器约定）。原三个模块均使用 500。统一后消除歧义。

### 3.2 `PageResult` 字段 `result` → `list`

解决原 `setRecords()` 自动覆盖 `total` 的 bug。前端期望字段名 `list`。

### 3.3 `start`/`end` 字段删除

经审阅确认没有任何调用方使用 `getStart()`/`setStart()`/`getEnd()`/`setEnd()`，安全去除。

### 3.4 不含 `error()` 和 `invalidParams()`

`ResponseResult` 不提供 `error()` 方法（各调用点改用 `fail()`），不提供 `invalidParams()`（不够通用）。

### 3.5 Auth 模块 POM 依赖链

`coder-club-auth-common/pom.xml` 也添加了 `coder-club-common` 依赖。这是因为 `LoginException` 和 `TokenException` 都 extends `BaseException`（来自 common 模块），而 auth-common 在 Maven 全量 reactor 构建中需要正确解析 classpath。

## 6. 经验总结

### 6.1 实现过程中的修复

全量构建时发现了 3 个单模块构建中未暴露的问题，均在 `a1d9c24` 修复：

| 问题 | 根因 | 修复 |
|------|------|------|
| `ResultCodeEnum` 缺少 `DATA_BIND_ERROR`/`SYSTEM_ERROR` | 设计枚举时遗漏（auth+subject 的 GlobalExceptionHandler 都有引用） | 追加两个枚举值 |
| `coder-club-auth-common` 编译找不到 `BaseException` | LoginException/TokenException imports 更新后需添加 `coder-club-common` 依赖 | auth-common pom 添加依赖 |
| `AuthUserDomainServiceImpl.setRecords()` | auth 模块的 PageResult 也有 `setRecords()` 调用（Task 3 的 sed 只替换了 import） | 改为 `setList()` |

**经验**：单模块 `-am` 构建可能因为 reactor 中依赖模块被提前安装而掩盖类路径问题。提交前必须以全量 `mvn install` 验证。

### 6.2 设计决策验证

- **Root pom 不添加 modules 声明** — 只加在 BOM 的 modules 中（否则 `DuplicateProjectException`）
- **common 模块的 parent 应为 `coder-club-dependencies`** 而非根 pom（与 oss/auth/subject 一致，并可获得 BOM 的 dependencyManagement）
- **common 模块需显式配置 lombok annotation processor**（非 auth aggregator POM 的子模块，因此编译器插件需独立配置）

## 3. 必须修复

### [必须修复] PageResult 的 totalPages 仍依赖 setter 调用顺序

**位置：** `coder-club-common/src/main/java/com/jackey/common/entity/res/PageResult.java:21-35`

`setTotal()` 会按照当前 `pageSize` 计算 `totalPages`，但 Lombok 生成的 `setPageSize()` 只修改 `pageSize`，不会重新计算 `totalPages`。因此当数据绑定或调用顺序是先设置 `total`、后设置 `pageSize` 时，分页结果会返回错误的总页数。

例如：先执行 `setTotal(25)`，对象使用默认 `pageSize=20` 计算出 `totalPages=2`，再执行 `setPageSize(10)` 后，`totalPages` 仍为 2，正确值应为 3。当前 `PageResultTest` 只覆盖了先设置 `pageSize`、再设置 `total` 的顺序，未覆盖反向顺序。

**建议：** 将 `setPageSize()` 改为显式方法并在 `total` 已存在时重新计算，或让 `getTotalPages()` 根据当前 `total` 和 `pageSize` 即时计算；同时增加两种 setter 顺序和 JSON 反序列化顺序的测试。

### [必须修复] Feign 内部调用没有透传 traceId，无法形成全链路日志关联

**位置：** `coder-club-subject/coder-club-subject-app/coder-club-subject-app-controller/src/main/java/com/jackey/subject/app/config/FeignConfig.java:12-18`、`coder-club-common/src/main/java/com/jackey/common/filter/TraceIdFilter.java:21-31`

`TraceIdFilter` 将入口请求的 `X-Trace-Id` 写入 MDC，但 Subject 的 `RequestInterceptor` 只设置了 `Authorization`，没有把 `MDC.get("traceId")` 写入 Feign 请求头。Subject 调用 Auth 的 `/auth/user/info` 时，Auth 收不到上游 traceId，会由自己的 Filter 重新生成一个 ID，导致同一业务请求在两项服务的日志中被拆成两条链路。

这与 M2 设计文档 D6/R5 中“Feign 链路靠 MDC 透传”的约定不一致，也使完工报告中“日志可追踪”和“traceId 全链路”结论不能成立。

**建议：** 在 Feign 拦截器中读取 MDC 的 `traceId` 并设置 `X-Trace-Id`，无 MDC 值时保持现有行为或生成统一 ID；补充 RequestTemplate 断言和 Subject → Auth 的集成验证。

## 5. 建议修改

### [建议修改] 入口 traceId 应限制格式和长度

**位置：** `coder-club-common/src/main/java/com/jackey/common/filter/TraceIdFilter.java:35-42`

当前代码直接接受任意非空的 `X-Trace-Id`，因此日志中的 traceId 不一定符合报告声称的 16 位小写十六进制格式，也允许超长值进入 MDC 和日志。建议对外部 header 做长度和字符集校验，非法值回退为服务端生成的 traceId，并补充超长、非法字符和空白值测试。

### [建议修改] PageResult.map() 应处理 null list

**位置：** `coder-club-common/src/main/java/com/jackey/common/entity/res/PageResult.java:38-44`

`setList()` 仍允许将 `list` 设为 null，而 `map()` 直接调用 `list.stream()`。共享分页对象一旦来自空列表字段或外部反序列化，映射会抛出 NullPointerException。建议将 null 视为空列表，或在 setter 中统一归一化，并增加对应测试。
